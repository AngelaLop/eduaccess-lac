## ⚠ Correction: the audit's CRITICAL finding is wrong

The audit reported as its top finding:

> **CRITICAL** — Live Supabase service-role key and Groq API key committed
> to the repo in `apps/web/.env.local` and `apps/worker/.env`.

**This is not true.** Hand-verified after the audit:

- `git ls-files | grep '\.env'` shows only `apps/worker/.env.example`
  (placeholder file, no real keys).
- `git log --all --diff-filter=A --name-only` confirms no `.env` /
  `.env.local` has ever been added to history.
- `.gitignore` covers `.env`, `.env*.local`, `*.pem`, and `.claude/`.
- Both .env files exist on the developer's local disk for local-dev only;
  the subagent read them directly even though its prompt explicitly said
  *"Don't read any .env files."* It then conflated "file exists on disk"
  with "file is committed."

**No remediation needed for credentials.** Existing keys are not exposed.
The lesson is about the audit method, not the project: keep subagents
on rails and verify their CRITICAL claims before acting.

## Verified findings (severity-ranked)

### HIGH — No per-IP rate limiting on `/api/ask`

**Layer:** AI Inputs and Rate Limits.
**Location:** `apps/web/app/api/ask/route.ts`.
**What's wrong:** The route is public and unauthenticated (by design — no
auth in v1-v3 scope). User input is bounded to 500 chars, but anyone with
the URL can call it in a loop and drain the Groq free-tier daily quota,
breaking the chat for everyone.
**Fix:** Add a per-IP rate limiter (in-process LRU or `@upstash/ratelimit`
if Vercel KV is enabled). 30 requests / 15 minutes per IP is generous and
still budget-safe.

### HIGH — No CI gate (`.github/workflows/` missing)

**Layer:** Pre-commit and CI Gates.
**Location:** Missing.
**What's wrong:** Pushes to `main` bypass type checking, linting, and any
secret-scanning. A typo that survives local dev can break Vercel's auto
deploy.
**Fix:** Add `.github/workflows/ci.yml` running `pnpm typecheck` +
`pnpm lint` on every push and PR.

### HIGH — No pre-commit hook (`.husky/` missing)

**Layer:** Pre-commit and CI Gates.
**Location:** Missing.
**What's wrong:** No local guardrail before a commit lands. Catches
typecheck regressions only after push.
**Fix:** Install Husky with a pre-commit hook running `pnpm typecheck`.
Keep the hook fast — heavy stuff (full builds, integration tests) belongs
in CI, not pre-commit.

### MEDIUM — No structured monitoring / LLM call accounting

**Layer:** Monitoring and Error Tracking.
**Location:** Repo-wide; `console.log` / `console.error` only.
**What's wrong:** Cannot answer "how many Groq calls did we make today,
how many failed, what's the daily token spend." Cost overruns and
prompt-injection attempts are invisible.
**Fix (deferred to v4):** Integrate Sentry (or Logflare) and add
structured log lines around every Groq call:
`{ route, model, prompt_tokens, completion_tokens, latency_ms, status }`.
For v3 this is over-budget — call it out in the v3 summary as known.

### MEDIUM — Permissive Claude Code agent settings

**Layer:** Supply Chain.
**Location:** `.claude/settings.local.json`.
**What's wrong:** Allowlist includes broad wildcards (`Bash(pnpm exec *)`,
`Bash(git push *)`, `Bash(git add *)`). `.claude/` itself is gitignored,
so this only affects the local dev's agent permissions, not other
collaborators. Still: less-broad allowlists reduce the blast radius if a
prompt-injection ever lands.
**Fix:** Tighten wildcards (e.g. `Bash(pnpm exec tsc *)` not
`Bash(pnpm exec *)`). Add an explicit deny list for `.env*` and `keys*.png`
in `CLAUDE.md` / `AGENTS.md`.

### LOW — No `apps/web/.env.example`

**Layer:** Dev/Preview/Prod Environments.
**Location:** Missing (`apps/web/.env.local` exists locally but no example
template is checked in).
**What's wrong:** A fresh clone has no template for required env vars
(`NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`,
`SUPABASE_SERVICE_ROLE_KEY`, `GROQ_API_KEY`, `GROQ_MODEL`).
**Fix:** Add `apps/web/.env.example` with placeholders matching the
existing `apps/worker/.env.example` style.

### LOW — No agent deny list in `CLAUDE.md`

**Layer:** Supply Chain.
**Location:** `CLAUDE.md` does not currently forbid agent writes to
`.env*`, `package.json`, `pnpm-lock.yaml`, `vercel.json`, `railway.json`.
**Fix:** Add an explicit deny-list section.

## Agent deny list (to add to CLAUDE.md)

```text
## Security: agent deny list

Claude Code and any other agents working on this project MUST NOT:

1. Read or modify .env, .env.local, .env.*.local files — these contain
   live API keys. Use .env.example files instead.
2. Commit any *.png file at the repo root (likely a credential
   screenshot) — keys.png and keys*.png are gitignored as a safety net.
3. Modify package.json or pnpm-lock.yaml without explicit user approval.
4. Modify vercel.json or railway.json — deployment configs are managed
   in the platform dashboards.
5. Run `git push --force`, `git reset --hard`, or any irreversible git
   operation without explicit user approval.
6. Log full user questions from /api/ask verbatim — log digests + length
   only. Never write user prompts to a public artifact.
```
